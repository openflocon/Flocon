# Flocon Protocol

Technical reference of every message exchanged between the **mobile SDK** (Android / iOS / JVM) and the **Flocon Desktop** app.

Source of truth:
- Mobile: `FloconAndroid/flocon/src/commonMain/kotlin/io/github/openflocon/flocon/Protocol.kt`
- Desktop: `FloconDesktop/domain/src/commonMain/kotlin/io/github/openflocon/domain/Protocol.kt`

## Transport

| Channel   | Direction        | Address                          | Usage                                  |
|-----------|------------------|----------------------------------|----------------------------------------|
| WebSocket | both             | `wss://<host>:9023/`              | All plugin messages (JSON text frames) |
| HTTPS     | mobile → desktop | `POST https://<host>:9024/upload` | File upload (see [files.md](files.md)) |

Both channels use TLS, so apps never need to allow cleartext traffic. The desktop serves a self-signed certificate (SAN `localhost` / `127.0.0.1`) that clients **must accept without verifying it** (trust-all, hostname check disabled): the TLS layer only encrypts the channel, it does not authenticate the desktop. The plain `ws://` / `http://` ports are no longer served.

On Android, the desktop runs `adb reverse tcp:9023 tcp:9023` and `adb reverse tcp:9024 tcp:9024`, so `<host>` is `localhost`.

## Envelopes

### Mobile → Desktop

| Key              | Type     | Description                                         |
|------------------|----------|-----------------------------------------------------|
| `deviceId`       | `String` | Unique device identifier                            |
| `deviceName`     | `String` | Human readable device name                          |
| `appName`        | `String` | Application name                                    |
| `appPackageName` | `String` | Application package / bundle id                     |
| `appInstance`    | `Long`   | SDK start timestamp (ms), identifies an app launch  |
| `platform`       | `String` | `android`, `ios`, `desktop`                         |
| `versionName`    | `String` | Flocon SDK version, ex: `1.3.0`                     |
| `plugin`         | `String` | Plugin name (see table below)                       |
| `method`         | `String` | Method name inside the plugin                       |
| `body`           | `String` | **JSON payload serialized as a string**             |

```json
{
  "deviceId": "emulator-5554",
  "deviceName": "Pixel 8",
  "appName": "My App",
  "appPackageName": "com.example.app",
  "appInstance": 1729260000000,
  "platform": "android",
  "versionName": "1.3.0",
  "plugin": "database",
  "method": "get_databases",
  "body": "[{\"id\":\"app_db\",\"name\":\"app_db\"}]"
}
```

The desktop identifies a client by the triple `deviceId` + `appPackageName` + `appInstance`.

### Desktop → Mobile

| Key      | Type     | Description                             |
|----------|----------|-----------------------------------------|
| `plugin` | `String` | Plugin name                             |
| `method` | `String` | Method name                             |
| `body`   | `String` | **JSON payload serialized as a string** (may be `""`) |

```json
{
  "plugin": "files",
  "method": "list_files",
  "body": "{\"requestId\":\"7f1c…\",\"path\":\"files\",\"isConstantPath\":true,\"withFoldersSize\":false}"
}
```

## Handshake (`bonjour`)

Right after a connection is opened, before any other message, the SDK sends `plugin: "bonjour"`, `method: "bonjour"` with this body:

| Key              | Type       | Description                                                                                          |
|------------------|------------|------------------------------------------------------------------------------------------------------|
| `plugins`        | `String[]` | Lowercase names of the plugins installed in the SDK (the desktop hides the other ones)               |
| `connectionType` | `String`   | `default` for the default address (localhost: adb reverse, simulator), `wifi` for the address given to the connect module |

```json
{ "plugins": ["network", "database"], "connectionType": "wifi" }
```

The desktop shows a wifi icon next to a device connected with `wifi`.

## Conventions used in this folder

- Examples of `body` are shown **decoded** (as real JSON) for readability. On the wire they are a JSON string inside the envelope.
- `T?` = nullable. Fields that are `null` **or** equal to their default value may be **omitted** (`encodeDefaults = false`).
- `List<X>` = JSON array of `X`. When a body or a field is a list, the item structure is described in its own table, named after `X`.
- `Map<String, String>` = JSON object with free keys and string values.
- `requestId` is generated by the desktop and echoed back by the mobile in the response, to match request / response.
- Timestamps are epoch milliseconds.
